# Motion design

Read Son compatibility before this playbook.

For web animation performance questions, start with `animation-performance` and the actual update path.
Do not run an opportunity survey or choose new motion for a specific frame-cost diagnosis.
Separate code-grounded risks from observed dropped frames and verify the cause with a recording when the task permits one.
A read-only code audit ends with findings and the recording still needed.

For new motion, use `animation-vocabulary` to establish terminology only when needed.
Use `find-animation-opportunities` when the user asks where motion could help, then `animate` or `animate-expo` for the target platform.
Use `review-animations` when the task includes assessment and `improve-animations` for a requested revision.
Inspect reduced-motion behavior and keyboard interaction in the rendered application.
